# SeatSense: เว็บจองพื้นที่อ่านหนังสือ KMUTT

เว็บสำหรับค้นหาและจองพื้นที่อ่านหนังสือ ห้องประชุม และพื้นที่ทำงานภายในมหาวิทยาลัย
ฝั่งหน้าเว็บเขียนด้วย JavaScript ล้วน (ES modules ไม่ใช้เฟรมเวิร์ก) ฝั่งเซิร์ฟเวอร์ใช้ Node.js + Express และเก็บข้อมูลใน PostgreSQL

## สถานะปัจจุบัน

**ใช้งานได้แล้ว**

- ดูรายการพื้นที่ ค้นหา และกรองตามประเภท (ข้อมูลมาจากฐานข้อมูล)
- เลือกวัน เวลา และที่นั่ง แล้วตรวจสอบว่าว่างจริงหรือไม่
- จองที่นั่ง โดยฐานข้อมูลป้องกันการจองซ้ำที่นั่งและช่วงเวลาเดียวกัน
- ดูรายการจองของฉัน เช็กอิน และยกเลิกการจอง (ข้อมูลยังอยู่หลังรีเฟรชหน้า)

**ยังไม่ได้ทำ**

- เข้าสู่ระบบจริง (ฟอร์มรหัสผ่านและปุ่ม Google / Microsoft / ModLink ยังไม่ได้เชื่อมระบบ)
- สมัครสมาชิก และการรีเซ็ตรหัสผ่าน
- QR code สำหรับเช็กอิน และการขยายเวลา (ยังเป็นข้อความตัวอย่าง)

## เทคโนโลยี

| ส่วน | เครื่องมือ |
|---|---|
| หน้าเว็บ | HTML, CSS, JavaScript (ES modules) |
| เซิร์ฟเวอร์ | Node.js 20.6 ขึ้นไป, Express |
| ฐานข้อมูล | PostgreSQL (ผ่านแพ็กเกจ `pg`) |

## สิ่งที่ต้องมี

- Node.js 20.6 ขึ้นไป (ตรวจสอบด้วย `node --version`)
- ฐานข้อมูล PostgreSQL หนึ่งฐาน (แนะนำแบบโฮสต์ ไม่ต้องติดตั้งเอง ดูด้านล่าง)

## เริ่มต้นใช้งานบนเครื่อง

### 1. ติดตั้งแพ็กเกจ

```sh
npm install
```

ถ้า `package.json` ยังไม่มีรายการ `dependencies` ให้ติดตั้งโดยตรง:

```sh
npm install express pg cookie-session
```

### 2. เตรียมฐานข้อมูล PostgreSQL

**ตัวเลือก A (แนะนำ): ฐานข้อมูลที่โฮสต์ให้**

1. สร้างโปรเจกต์ฟรีที่ Neon หรือ Supabase (หรือเพิ่มผ่านแท็บ Storage / Marketplace ใน Vercel)
2. เปิดหน้า connection details แล้วคัดลอก connection string หน้าตาประมาณ
   `postgres://user:password@ep-xxxx.region.aws.neon.tech/dbname?sslmode=require`
3. ถ้ามีให้เลือกทั้งแบบ pooled และ direct ให้ใช้แบบ pooled

**ตัวเลือก B: PostgreSQL บนเครื่องตัวเอง**

1. ติดตั้ง PostgreSQL จาก postgresql.org (ตัวติดตั้งจะให้ตั้งรหัสผ่านของผู้ใช้ `postgres` ให้จำไว้)
2. สร้างฐานข้อมูลว่างชื่อ `seatsense` ผ่าน pgAdmin หรือคำสั่ง `createdb -U postgres seatsense`
3. ตรวจสอบว่าบริการ PostgreSQL กำลังทำงานอยู่ (Windows: เปิด Services แล้วดู `postgresql-x64-...`)

### 3. ตั้งค่าไฟล์ `.env`

คัดลอกไฟล์ตัวอย่างแล้วกรอกค่า:

```sh
# Windows (Command Prompt)
copy .env.example .env

# macOS / Linux / PowerShell / Git Bash
cp .env.example .env
```

มีสองค่าที่ต้องกรอก:

```text
DATABASE_URL=postgres://user:password@host:5432/dbname?sslmode=require
SESSION_SECRET=ข้อความสุ่มยาว ๆ
```

- `DATABASE_URL` คือ connection string จากขั้นตอนที่ 2
  สำหรับฐานข้อมูลบนเครื่อง จะเป็นแบบ `postgres://postgres:รหัสผ่าน@localhost:5432/seatsense` (ไม่ต้องใส่ `?sslmode=require`)
  ถ้ารหัสผ่านมีอักขระพิเศษ เช่น `@ # / :` ต้องแปลงเป็นรหัส URL (เช่น `@` เป็น `%40`)
- `SESSION_SECRET` คือข้อความสุ่มที่ใช้เซ็นกำกับ cookie สร้างได้ด้วยคำสั่ง:
  ```sh
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
- เขียนแบบ `ชื่อ=ค่า` ไม่ต้องมีเครื่องหมายคำพูดและไม่มีช่องว่างรอบเครื่องหมาย `=`
- **ห้าม commit ไฟล์ `.env`** (ถูกใส่ใน `.gitignore` แล้ว แต่ควรตรวจด้วย `git status`)

### 4. สร้างตารางและข้อมูลตัวอย่าง

```sh
npm run db:setup
```

ถ้าสำเร็จจะแสดง `Database ready.` คำสั่งนี้รันซ้ำได้โดยไม่ทำให้ข้อมูลซ้ำ

### 5. เปิดเว็บ

```sh
npm run dev
```

แล้วเข้า `http://localhost:3000`

ไม่ต้องใช้ `python3 -m http.server` อีกต่อไป และไม่ควรใช้เด็ดขาด เพราะจะเปิดไฟล์ทั้งโปรเจกต์ รวมถึง `.env` ให้ดาวน์โหลดได้

## ดูข้อมูลในฐานข้อมูล

ฐานข้อมูลมี 4 ตาราง: `users`, `spaces`, `seats`, `bookings`

- **Neon:** เปิดโปรเจกต์ แล้วใช้แท็บ Tables หรือ SQL Editor
- **Supabase:** เมนู Table Editor ด้านซ้าย
- **PostgreSQL บนเครื่อง:** เปิด pgAdmin แล้วไปที่ Databases → `seatsense` → Schemas → public → Tables คลิกขวาที่ตาราง เลือก View/Edit Data → All Rows

หรือรันคำสั่ง SQL ใน SQL editor:

```sql
SELECT * FROM spaces;     -- พื้นที่ตัวอย่าง 3 แห่ง
SELECT * FROM seats;      -- ที่นั่งตัวอย่าง
SELECT * FROM bookings;   -- ว่างจนกว่าจะมีการจองผ่านเว็บ
```

## นำขึ้น Vercel

1. Commit ไฟล์ `package.json` **และ** `package-lock.json` ขึ้น Git (ห้ามรวม `.env`)
2. ที่ Vercel ไปที่ Project Settings → Environment Variables แล้วเพิ่ม `DATABASE_URL` และ `SESSION_SECRET`
   (ถ้าเพิ่มฐานข้อมูลผ่าน Marketplace แล้วชื่อตัวแปรไม่ตรงกัน ให้เพิ่ม `DATABASE_URL` เองด้วยค่าเดียวกัน)
3. รัน `npm run db:setup` หนึ่งครั้งจากเครื่องของคุณ โดยให้ `DATABASE_URL` ใน `.env` ชี้ไปที่ฐานข้อมูลที่โฮสต์ไว้
4. Push แล้วทดสอบบน **Preview deployment** ก่อนขึ้น Production

Vercel จะเสิร์ฟไฟล์ใน `public/` ผ่าน CDN และรัน `src/index.js` เป็นฟังก์ชันสำหรับ `/api/*`
เนื่องจากเซิร์ฟเวอร์ไม่มีดิสก์ถาวร จึงใช้ฐานข้อมูลที่โฮสต์ไว้ และใช้ session แบบเก็บใน cookie

### ตรวจสอบหลัง deploy

แทน `YOUR-PREVIEW-URL` ด้วยที่อยู่จริง (บน Windows PowerShell ให้พิมพ์ `curl.exe` แทน `curl`):

```sh
curl -i https://YOUR-PREVIEW-URL/api/spaces          # ต้องได้ 200 และรายการพื้นที่ 3 แห่ง
curl -i https://YOUR-PREVIEW-URL/src/index.js        # ต้องไม่ได้โค้ดเซิร์ฟเวอร์ (คาดหวัง 404)
curl -i https://YOUR-PREVIEW-URL/scripts/schema.sql  # คาดหวัง 404
curl -i https://YOUR-PREVIEW-URL/package.json        # คาดหวัง 404
```

จากนั้นทดสอบในเบราว์เซอร์: เลือกพื้นที่ จองที่นั่ง รีเฟรชหน้าแล้วเปิด "รายการจอง" ต้องยังเห็นการจองอยู่
ลองจองที่นั่งและช่วงเวลาเดิมซ้ำ ต้องไปที่หน้า "ช่วงเวลานี้ไม่ว่าง"

## API

| Method | เส้นทาง | หน้าที่ |
|---|---|---|
| GET | `/api/spaces` | รายการพื้นที่ พร้อมสถานะว่างของวันนี้ |
| GET | `/api/spaces/:id` | รายละเอียดพื้นที่และที่นั่งทั้งหมด |
| GET | `/api/spaces/:id/availability?date=YYYY-MM-DD&slot=...` | ที่นั่งที่ยังว่างในวันและช่วงเวลานั้น |
| GET | `/api/bookings` | รายการจองของผู้ใช้ปัจจุบัน |
| POST | `/api/bookings` | สร้างการจอง (`seatId`, `date`, `slot`, `attendees`) |
| POST | `/api/bookings/:id/checkin` | เช็กอิน |
| POST | `/api/bookings/:id/cancel` | ยกเลิกการจอง |

เซิร์ฟเวอร์ตรวจสอบข้อมูลทุกครั้ง และทุกคำสั่งเปลี่ยนการจองจะตรวจว่าเป็นการจองของผู้ใช้คนนั้นจริง

## แก้ไขและพัฒนาต่อ

1. **กำหนดงานของผู้ใช้ก่อน**: เขียนว่าใครเข้ามาใช้เว็บ ต้องการทำอะไร และต้องผ่านขั้นตอนใด เช่น ค้นหาพื้นที่ → เลือกเวลา → ยืนยันการจอง
2. **ร่าง wireframe**: วางลำดับข้อมูลและปุ่มของแต่ละหน้าก่อนเลือกสีหรือรายละเอียดตกแต่ง
3. **แก้เนื้อหาของหน้า**: เปิดไฟล์ใน `public/src/pages/` ที่ตรงกับหน้าที่ต้องการ เช่น หน้า login อยู่ใน `login.js` หน้าค้นหาอยู่ใน `spaces.js`
4. **ปรับหน้าตา**: ใช้ class ที่มีอยู่แล้วหรือเพิ่ม class ใน page module แล้วเขียน CSS ใน `public/src/styles.css`
5. **เพิ่มหรือแก้พื้นที่และที่นั่ง**: แก้ `scripts/seed-data.js` แล้วรัน `npm run db:setup` ใหม่
   (คำสั่งนี้เพิ่มและอัปเดตข้อมูล แต่ไม่ลบที่นั่งที่ถูกเอาออกจากไฟล์ ถ้าต้องการลบให้ลบในฐานข้อมูลโดยตรง)
6. **เพิ่มพฤติกรรมของหน้าเว็บ**: แก้ state เริ่มต้นใน `public/src/app/state.js` การกดปุ่มและส่งฟอร์มใน `public/src/app/actions.js` และเพิ่มการจับคู่หน้าใน `public/src/app/screens.js`
7. **เพิ่มหรือแก้ API**: เพิ่มเส้นทางใน `src/routes/` ถ้าต้องเปลี่ยนโครงสร้างตาราง ให้แก้ `scripts/schema.sql` และเขียนคำสั่ง `ALTER TABLE` สำหรับฐานข้อมูลที่มีข้อมูลอยู่แล้ว

ตัวอย่างการไล่แก้: เปลี่ยนข้อความปุ่มล็อกอิน → `public/src/pages/login.js`; เปลี่ยนสีปุ่มหลัก → `.primary-action` ใน `public/src/styles.css`; เพิ่มหน้าจองใหม่ → เพิ่ม page module แล้วลงทะเบียนใน `screens.js` และเพิ่ม action ใน `actions.js`

ข้อควรระวัง: ห้ามวางความลับหรือโค้ดฝั่งเซิร์ฟเวอร์ไว้ใน `public/` เพราะทุกไฟล์ในโฟลเดอร์นี้ผู้ใช้ดาวน์โหลดได้

## ส่วนที่ยังเป็นของชั่วคราวและข้อจำกัด

- **การเข้าสู่ระบบ**: ฟอร์มรหัสผ่านและปุ่ม Google / Microsoft / ModLink ยังไม่ได้เชื่อมระบบ
  การจองครั้งแรกจากเบราว์เซอร์หนึ่งจะสร้างผู้ใช้ guest แบบไม่ระบุตัวตน เก็บไว้ใน cookie ที่เซ็นกำกับ
  แต่ละคนเห็นเฉพาะการจองของตัวเอง ถ้าล้าง cookie จะมองไม่เห็นการจองเดิม
  (แผนต่อไปคือ OAuth กับ Google / Microsoft และจำกัดเฉพาะอีเมล `@mail.kmutt.ac.th`
  ส่วน ModLink ต้องสอบถามผู้ดูแลระบบมหาวิทยาลัยก่อนว่ามี API สำหรับเข้าสู่ระบบหรือไม่)
- **ขยายเวลา**: ยังแสดงเป็นข้อความตัวอย่าง ไม่ได้บันทึกลงฐานข้อมูล
- **เปลี่ยนแปลงการจอง**: ปุ่มนี้เปิดฟอร์มเลือกเวลาและสร้างการจอง **ใหม่** โดยยังไม่ยกเลิกการจองเดิม
- **ช่วงเวลา (slots)** มี 2 ที่ที่ต้องตรงกัน: `public/src/pages/booking.js` และ `src/slots.js`
- **สถานะ "ว่าง"** ในรายการพื้นที่ หมายถึงยังมีที่นั่งและช่วงเวลาว่างอย่างน้อยหนึ่งช่องในวันนี้ ยังไม่คำนึงถึงช่วงเวลาที่ผ่านไปแล้ว
- **ที่นั่งตัวอย่าง** ใน `scripts/seed-data.js` ยังไม่ตรงกับความจุจริงของแต่ละพื้นที่
- **เช็กอิน** ยังไม่จำกัดเฉพาะวันที่จอง และยังไม่มี QR code จริง

| ข้อความที่พบ | สาเหตุและวิธีแก้ |
|---|---|
| `ECONNREFUSED ... 5432` | เชื่อมต่อฐานข้อมูลบนเครื่องไม่ได้ ตรวจว่า `DATABASE_URL` ชี้ไปที่ฐานข้อมูลที่ถูกต้อง หรือถ้าใช้ PostgreSQL บนเครื่อง ให้ตรวจว่าบริการกำลังทำงาน ตรวจโฮสต์ที่ใช้อยู่ด้วย `node --env-file=.env -e "console.log(new URL(process.env.DATABASE_URL).host)"` |
| `Invalid URL` | `DATABASE_URL` ผิดรูปแบบ มักเกิดจากรหัสผ่านที่มีอักขระพิเศษ ให้แปลงเป็นรหัส URL หรือคัดลอก connection string จากผู้ให้บริการทั้งสายโดยไม่แก้ไข |
| `DATABASE_URL is not set` / `SESSION_SECRET is not set` | ไม่พบไฟล์ `.env` หรือยังไม่ได้กรอกค่า ตรวจว่าไฟล์ชื่อ `.env` (ไม่ใช่ `.env.txt` ซึ่ง Windows มักซ่อนนามสกุลไว้) และอยู่ที่โฟลเดอร์หลักของโปรเจกต์ |
| หน้าเว็บขึ้น "โหลดข้อมูลพื้นที่ไม่สำเร็จ" | เซิร์ฟเวอร์ยังไม่ทำงาน หรือยังไม่ได้รัน `npm run db:setup` เปิดดูข้อความผิดพลาดในหน้าต่างที่รัน `npm run dev` |
| ต้องล็อกอินใหม่หรือการจองหายหลังรีเฟรช | cookie ถูกล้าง หรือ `SESSION_SECRET` ถูกเปลี่ยน (การเปลี่ยนค่านี้ทำให้ทุกคนหลุดจากระบบ) |
| `--env-file` ไม่รู้จัก | Node.js เก่ากว่า 20.6 ให้อัปเดต Node.js |
